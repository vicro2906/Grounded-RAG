## Absolute rule: fidelity over completeness

Healthcare professionals will use the chatbot to make real clinical decisions. A hallucination about an antiretroviral dose, a drug interaction or a diagnostic criterion can harm the patient. Therefore:

- **Do not describe the PDF's images, diagrams or algorithms with an LLM**, nor try to "reconstruct" tables that come out broken. - **Do not invent headings** nor reorder the content.

If while inspecting the PDF you detect it is a scan (not native), **stop and let me know** before continuing; do not run OCR on your own.

### 2. Building the script

Build a self-contained Python script (`convert_guideline.py`) adapted to the peculiarities you discovered. It should cover at least:

**Preserve faithfully:**
- Running body text
- Headings with hierarchy well reconstructed according to the document's numbering
- Bold, italics, in-body bibliographic citations (`[2]`, `[1,3]`)
- Evidence/recommendation grades
- Lists, enumerations
- Markdown tables only if they are real semantic tables (not layouts)

**Omit with a warning marker (`> _[... omitido — consultar PDF original]_`):**
- OCR blocks that `pymupdf4llm` inserts between `**----- Start of picture text -----**` and `**----- End of picture text -----**` (disordered text, clinically useless)
- Image placeholders like `**==> picture [WxH] intentionally omitted <==**`
- Malformed tables. Reasonable heuristics: >6 columns, >50% empty cells, or a very irregular column count across rows → almost certainly a layout, discard. Keep the ones that pass the filters, but count them in the statistics so I can review them.

**Additional cleanup:**
- "Strikethrough" (`~~text~~`): pymupdf4llm generates it for text highlighted in yellow in the PDF (not actually struck through). By default, **remove the `~~` markers and keep the text**. Add a flag to keep them in case it is needed.
- Repetitive footer: detect it automatically (long lines that repeat many times) and remove it.
- Stray page numbers on their own line.
- Multiple consecutive blank lines → at most two.

**Heading-hierarchy reconstruction** (this is critical for the chunking):

By default, `pymupdf4llm` puts all headings at the same level (`##`). Reassign levels according to the numbering:
- One-level numbering (`1.`) → H2
- Two levels (`1.2.`) → H3
- Three levels (`1.2.3.`) → H4
- And so on

For special unnumbered headings, assign the level consistent with their structural role (e.g. "Recomendaciones" is usually H4 within a clinical section; "Bibliografía" closes each numbered section and usually goes to H3; "Anexo" or "Agradecimientos" usually go to H2). Adapt the levels to what you see in *this* guide.

Additional heading cleanup:
- Remove leading junk that pymupdf4llm drags along (`- 2.2.3.` → `2.2.3.`, stray asterisks)
- Remove redundant bold inside the `#` (`## **Texto**` → `## Texto`)
- **Merge headings broken across two lines** by the typesetter's column breaks. Detection: a heading ending in a preposition/connector ("con", "de", "del", "en", "para", "y", "o", "a", "la", "el", "los", "las", "al", "ante", "sobre", "tras", "por", "sin", comma) followed by a short line with no heading formatting, or by an empty line + another short heading of the same level. Merge into a single heading.
- Demote bibliographic references slipped in as headings (`## 35. Workowski K. ... 2021;` → plain text). Pattern: starts with a number, an author with a capital letter, contains a year or "et al".

The script must print clear statistics: characters before/after, OCR blocks removed, images omitted, unreliable tables discarded, tables kept, highlights unmarked, headings normalized, broken headings merged.
